# Plan 3 — Design system et front : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** Livrer le front React de Digimmo hors éditeur : design system « Calque d'architecte » (tokens, composants, page catalogue), pages de compte, tableau de bord des projets, création et paramètres de projet, administration du catalogue — branché sur l'API du plan 2.

**Architecture :** SPA React 19 + Vite dans `apps/front`. Routage `react-router` (mode bibliothèque), données serveur via TanStack Query au-dessus d'un petit client `fetch` (`credentials: 'include'`, erreurs typées `ApiError`). Styles en CSS Modules au-dessus de variables CSS globales (tokens). En dev, Vite proxifie `/api` vers `http://localhost:3000` : le cookie de session reste en même origine.

**Tech Stack :** React 19, Vite 8, TypeScript, `react-router` 7, `@tanstack/react-query` 5, CSS Modules, polices `@fontsource/ibm-plex-{sans,serif,mono}` (auto-hébergées), Vitest + Testing Library + jsdom, MSW 2 (simulation de l'API), `vitest-axe` (accessibilité).

**Spec :** `docs/superpowers/specs/2026-11-23-digimmo-design.md` (§6 Front, §7 Interface et design system). API : `docs/superpowers/plans/2026-11-24-plan-2-api.md` (routes et formats).

## Global Constraints

- Interface **en français** ; cible **ordinateur**, pages hors éditeur **responsives** (largeur min. testée 360 px).
- Tokens (variables CSS, noms exacts) : `--papier #f4efe4`, `--papier-2 #ebe4d4`, `--trait #c9bfa8`, `--encre #2b3a55`, `--encre-2 #5a6680`, `--sanguine #a33a2f`, `--sauge #3f6b41`, `--ocre #845a10`, `--blanc #fbf8f1`. *(Sauge et ocre foncées par rapport à la maquette pour atteindre le contraste AA ≥ 4,5:1 exigé par la conception sur papier, papier-2 et blanc — choix du concepteur.)* Aucune couleur en dur hors `tokens.css`.
- Typographie : **IBM Plex Serif pour les titres seulement**, **Plex Sans pour toute l'interface**, **Plex Mono pour les cotes, dimensions et surfaces**.
- Composants du système réutilisés partout, **jamais de style ad hoc** : `Button` (primary / secondary / ghost / danger × md / sm), `Field` (ligne de cote, état erreur + message), `RuleBadge` (ok / alerte / erreur, **icône ✓ / ! / ✗ + texte**, la couleur n'est jamais seule), `ToolButton` (état actif), `ProjectCard`, plus `Alert`, `Modal`, `PageHeader` ajoutés ici.
- Accessibilité : navigation clavier complète, focus visible, chaque champ a un label, erreurs reliées par `aria-describedby` + `aria-invalid`, aucune violation `axe` sur chaque page testée.
- Unités : l'API parle en **centimètres entiers** ; l'utilisateur saisit des **mètres** (virgule ou point) ; affichage via `formatMeters` / `formatArea` de `@digimmo/domain`.
- Toutes les requêtes passent par `api()` (jamais de `fetch` direct dans un composant).
- Avertissement visible (accueil + pied de page) : « Digimmo ne remplace ni un architecte ni un constructeur. Les plans sont indicatifs. »
- TDD : chaque comportement commence par un test qui échoue ; pour le pur visuel (styles), un test léger après coup suffit.

## Review Focus

1. **Saisie en mètres avec virgule, point ou espaces** (`"20,5"`, `"20.5"`, `" 20 "`) → même valeur 2050 cm ; `"abc"`, `"-3"`, `"0"` → erreur sur le champ, aucune requête envoyée. Test : Task 6.
2. **Session expirée en cours d'utilisation** (n'importe quelle requête répond 401) → redirection vers `/connexion?suite=<page courante>`, pas d'écran blanc. Test : Task 3.
3. **Erreurs de validation du serveur** (400 avec `issues`) → message lisible dans une `Alert` (et sur le champ quand le chemin correspond), jamais `[object Object]`. Test : Task 4.
4. **Double clic sur un bouton d'envoi** → une seule requête (bouton désactivé pendant l'envoi). Test : Task 6.
5. **Utilisateur non admin sur `/admin/catalogue`** → page « Accès réservé aux administrateurs. », aucun élément d'administration rendu, même brièvement. Test : Task 8.
